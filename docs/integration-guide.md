# 接口与用户流程

## 登录与注册

动态站通过 Neon Auth 的 `/api/auth/*` 路由完成邮箱密码注册、登录、退出和邮件验证。QQ 邮箱只作为用户邮箱和发信通道；SMTP 授权码只配置在 Neon Auth 的邮件提供方，不能进入浏览器、源码或 Vercel 的公开变量。

登录成功后，浏览器持有由认证服务设置的安全会话 Cookie。`/account` 的访问控制和所有业务 API 都以该会话作为唯一身份来源。

## 业务 API

| 方法与路径 | 成功结果 | 未登录行为 | 说明 |
| --- | --- | --- | --- |
| `POST /api/profile` | 保存当前用户的姓氏、昵称、显示账号 | `401` | 请求体不能指定用户 ID |
| `POST /api/articles/:slug/favorite` | 收藏或取消当前用户对文章的收藏 | `401` | 通过会话确定用户；重复收藏不会产生重复行 |

客户端应把 `401` 视为需要登录，而不是重试或提示具体账户是否存在。服务端应只返回可安全展示的验证错误，不能把数据库连接信息、密码或 SMTP 信息带入响应。

## 收藏交互

1. 访客进入具体文章页 `/writing/[slug]`。
2. 文章详情页展示收藏入口；若无会话，入口跳转至登录页并保留原文章的返回地址。
3. 登录用户点击收藏或取消收藏；前端调用对应文章 slug 的受保护 API。
4. 服务器读取会话对应的用户，并只修改该用户自己的收藏记录。
5. `/account` 展示当前用户的收藏列表，并链接回文章详情页。

文章卡片、文章列表和首页均不提供直接收藏操作。
